# Secure Banking RAG Engine (Local Inference)

A privacy-first, on-premise Retrieval-Augmented Generation (RAG) pipeline designed for querying highly sensitive regulatory documents (e.g., RBI KYC Master Directions). 

This project demonstrates how enterprise banking environments can leverage LLMs safely without exposing proprietary policy data or customer information to third-party cloud APIs (like OpenAI or Anthropic), maintaining absolute compliance with financial data isolation mandates.

## Architecture Highlights

* **Zero Data Leakage:** 100% local inference utilizing an 8-billion parameter Llama 3 foundation model via Ollama. No data ever leaves the host machine.
* **Custom Hybrid Search:** Bypassed standard, opaque ensemble library wrappers to build a deterministic mathematical merger of dense semantic and sparse lexical search layers.
  * **Semantic (Dense):** ChromaDB vector index tracking embeddings generated by `all-MiniLM-L6-v2` for conceptual, contextual intent matching.
  * **Lexical (Sparse):** Pure BM25 keyword matching engine to catch exact regulatory codes, statutory terms, and precise compliance timelines.
* **Token Optimization & Deduplication:** Implemented a dictionary-based lookahead deduplication layer. By removing duplicate context windows before prompt compilation, the system reduces inference latency, saves context tokens, and mitigates the risk of duplicate-context hallucinations.
* **Component Isolation:** Enforces clean architecture boundaries. Ingestion, retrieval, and generation are decoupled into independently testable modules containing isolated script execution hooks.

## Technical Installation & Setup Guide

### 1. Prerequisite Environment Configuration

Ensure your local system has Python 3.10+ and the Ollama runtime installed.

* **Ollama (Local LLM Server):** Download and install from [Ollama's official site](https://ollama.com/).
* **Pull the Foundation Model:** Open your system terminal and run the following command to download the Llama 3 model locally:
```bash
ollama pull llama3

```



### 2. Repository Setup

Clone this repository to your local machine, initialize your isolated virtual environment, and install the verified dependencies:

```bash
# Navigate to the project root
cd bank_rag_api

# Create and activate a isolated Python virtual environment
python -m venv venv
source venv/Scripts/activate  # On Windows PowerShell: .\venv\Scripts\Activate.ps1

# Install required deep learning and data science packages
pip install -r requirements.txt

```

### 3. Placing the Regulatory Data

Create a `data/` directory at the root level and place your target regulatory document inside it. Rename it to match the ingestion pathway configuration:

```bash
mkdir data
# Move your target compliance PDF into this folder and name it: rbi_kyc_master.pdf

```

## Execution & Verification Lifecycle

The pipeline is split into two explicit operational phases: Ingestion (Write) and Query Generation (Read).

### Phase 1: Running Document Ingestion

Run the ingestion engine to parse the PDF document, split it into optimized semantic chunks, compute vector embeddings, and serialize them into your local disk database:

```bash
python -m src.ingestion

```

*Expected Output Logs:*

```text
1. Loading PDF from data/rbi_kyc_master.pdf...
2. Splitting text into chunks...
Created 103 text chunks.
3. Downloading Open-Source Embedding Model...
4. Generating Vectors and Saving to ChromaDB...

Success! Vector database saved locally at: vector_db

```

### Phase 2: Querying the Engine (Local Inference)

Run the generator orchestration script. The system will prompt you for an analytical query, run the dual-layer search, isolate the context, and send the deterministic prompt to your local GPU/CPU running Llama 3.

```bash
python -m src.generator

```

### Strategic Validation:

The foundation model correctly identifies the strict regulatory threshold (**once in every eight years**) because the sparse BM25 retriever surfaced the exact statistical rule matches, while the dense semantic layer maintained context regarding "risk classification," preventing the LLM from hallucinating standard 2-year (high-risk) or 10-year (low-risk) industry timelines.
